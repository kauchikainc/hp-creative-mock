# HP Mock Sample - 作業計画書

## 目的

このドキュメントは、HP Mock Sample プロジェクトの実装を進めるための詳細な作業計画を定義します。
TDD（テスト駆動開発）のアプローチに従い、各作業項目について「テスト作成 → テスト実行・失敗確認 → 実装 → テスト成功」のサイクルで進めます。

## 開発方針

### TDDサイクル

1. **RED**: テストを書き、実行して失敗を確認する
2. **GREEN**: テストをパスする最小限の実装を行う
3. **REFACTOR**: コードをリファクタリングして品質を高める
4. **COMMIT**: 各サイクル完了時にコミットする

### コミット戦略

- テスト作成後、テストが正しいことを確認したらコミット
- 実装完了後、すべてのテストがパスしたらコミット
- 機能単位で細かくコミットし、履歴を追いやすくする

### コメント方針

- すべてのコンポーネント、関数に日本語コメントを記載
- 複雑なロジックには説明コメントを追加
- 型定義にはJSDocコメントを記載

### デザイン方針

**重要**: このプロジェクトのモックは実際の商用サイトとして違和感のないデザインを実装します。

1. **高品質な画像の使用**
   - Unsplash、Pexels等から高解像度の実写画像を使用
   - プレースホルダー画像は使用しない

2. **リッチなアニメーション**
   - Framer Motionを使用
   - スクロールトリガー、ホバーエフェクト、トランジションを実装

3. **AI感の排除**
   - テキストは自然で具体的な表現
   - レイアウトは実際の商用サイトを参考
   - カラースキームは業種に適した配色

4. **プロフェッショナルな仕上がり**
   - クライアントにそのまま提示できるクオリティ
   - 細部までこだわったUI/UX

### 業種の拡張性

このプロジェクトは将来的に多数の業種を追加する前提で設計されています。
現在は不動産と中古車を実装しますが、以下の業種を順次追加予定:
- 建設業
- 美容院
- 飲食店
- 医療機関
- 士業
- ECサイト

## 補足事項

### コミットメッセージの形式

```
<type>: <subject>

[optional body]

🤖 Generated with [Claude Code](https://claude.com/claude-code)

Co-Authored-By: Claude <noreply@anthropic.com>
```

**type**:
- `feat`: 新機能
- `fix`: バグ修正
- `test`: テスト追加・修正
- `refactor`: リファクタリング
- `style`: コードスタイルの修正
- `docs`: ドキュメント
- `chore`: その他

### ブランチ戦略

- `main`: 本番ブランチ
- 機能追加は直接 `main` にコミット（小規模プロジェクトのため）

### トラブルシューティング

- テストが失敗する場合は、実装を見直す前にテスト自体が正しいか確認
- LocalStorageのテストでエラーが出る場合は、jest.setup.jsでモックが正しく設定されているか確認
- ビルドエラーが出る場合は、型定義が正しくエクスポート/インポートされているか確認
