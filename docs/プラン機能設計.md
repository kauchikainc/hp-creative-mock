# プラン機能設計書

## 1. プラン概要

HP Mock Sample では、各業種において **Standard** と **Premium** の2つのプランを提供します。

### 1.1 プランの違い

| カテゴリ | Standard | Premium |
|---------|----------|---------|
| **基本機能** | | |
| ヒーローセクション | ✓ | ✓ |
| 会社概要 | ✓ | ✓ |
| 検索フォーム | ✓ | ✓ |
| お問い合わせフォーム | ✓ | ✓ |
| **CMS機能** | | |
| ブログ | ✗ | ✓ |
| お知らせ・ニュース | ✗ | ✓ |
| **業種別機能** | | |
| 在庫管理（物件/車両） | ✗ | ✓ |
| 販売実績表示 | ✗ | ✓ |

## 2. 技術的実装方針

### 2.1 アーキテクチャパターン

**コンポーネント合成 + 条件付きレンダリング**

このアプローチにより:
- コードの重複を最小化
- 保守性の向上
- 型安全性の保証
- 拡張性の確保

### 2.2 実装パターン

#### パターン1: PremiumFeatures ラッパーコンポーネント

```tsx
<PremiumFeatures plan={plan}>
  <BlogSection />
</PremiumFeatures>
```

**利点**:
- 宣言的で読みやすい
- 再利用性が高い
- テストしやすい

#### パターン2: 機能フラグによる条件分岐

```tsx
{features.hasBlog && <BlogSection />}
```

**利点**:
- シンプル
- パフォーマンスが良い
- 細かい制御が可能

### 2.3 採用する実装パターン

両方のパターンを適材適所で使用:

- **大きなセクション**: PremiumFeatures ラッパー
- **小さな要素**: 機能フラグ

## 3. プラン判定ロジック

### 3.1 型定義

```typescript
// types/plan.ts

/** プラン種別の定数 */
export const PLANS = {
  STANDARD: 'standard',
  PREMIUM: 'premium',
} as const;

/** プラン型 */
export type Plan = typeof PLANS[keyof typeof PLANS];

/** プラン別機能設定 */
export interface PlanFeatures {
  /** お問い合わせフォームの有無 */
  hasContactForm: boolean;

  /** CMS機能の有無 */
  hasCMS: boolean;

  /** ブログ機能の有無 */
  hasBlog: boolean;

  /** お知らせ・ニュース機能の有無 */
  hasNews: boolean;

  /** 在庫管理機能の有無 */
  hasInventoryManagement: boolean;

  /** 販売実績表示の有無（業種依存） */
  hasSalesHistory?: boolean;
}
```

### 3.2 判定関数

```typescript
// lib/planUtils.ts

/**
 * Premiumプランかどうかを判定
 * @param plan - 判定対象のプラン
 * @returns Premiumプランの場合true
 */
export const isPremiumPlan = (plan: Plan): boolean => {
  return plan === PLANS.PREMIUM;
};

/**
 * プラン別の機能設定を取得
 * @param plan - 対象プラン
 * @returns プラン別の機能設定オブジェクト
 */
export const getPlanFeatures = (plan: Plan): PlanFeatures => {
  // Standard プランの基本機能
  const baseFeatures: PlanFeatures = {
    hasContactForm: true,
    hasCMS: false,
    hasBlog: false,
    hasNews: false,
    hasInventoryManagement: false,
  };

  // Premium プランの場合、CMS機能を追加
  if (isPremiumPlan(plan)) {
    return {
      ...baseFeatures,
      hasCMS: true,
      hasBlog: true,
      hasNews: true,
      hasInventoryManagement: true,
      hasSalesHistory: true,
    };
  }

  return baseFeatures;
};
```

## 4. コンポーネント設計

### 4.1 PremiumFeatures ラッパーコンポーネント

```typescript
// components/layout/PremiumFeatures.tsx

interface PremiumFeaturesProps {
  /** 現在のプラン */
  plan: Plan;

  /** Premium機能として表示する内容 */
  children: React.ReactNode;

  /** Standard プランの場合に表示する代替コンテンツ */
  fallback?: React.ReactNode;
}

/**
 * Premium プラン専用機能のラッパーコンポーネント
 *
 * Premium プランの場合のみ children をレンダリング。
 * Standard プランの場合は fallback をレンダリング（指定されている場合）。
 */
export default function PremiumFeatures({
  plan,
  children,
  fallback = null,
}: PremiumFeaturesProps) {
  if (isPremiumPlan(plan)) {
    return <>{children}</>;
  }

  return <>{fallback}</>;
}
```

### 4.2 使用例

#### 例1: ブログセクションの表示

```tsx
// components/templates/RealEstateTemplate.tsx

export default function RealEstateTemplate({
  companyInfo,
  plan,
}: TemplateProps) {
  const features = getPlanFeatures(plan);

  return (
    <BaseLayout companyInfo={companyInfo} industry="real-estate">
      <HeroSection />
      <SearchForm />
      <PropertyList />

      {/* Premium プランのみ: ブログセクション */}
      <PremiumFeatures plan={plan}>
        <BlogSection />
      </PremiumFeatures>

      {/* Premium プランのみ: お知らせセクション */}
      <PremiumFeatures plan={plan}>
        <NewsSection />
      </PremiumFeatures>

      <ContactForm />
    </BaseLayout>
  );
}
```

#### 例2: 機能フラグによる細かい制御

```tsx
// components/real-estate/PropertyList.tsx

export default function PropertyList({ plan }: { plan: Plan }) {
  const features = getPlanFeatures(plan);

  return (
    <section>
      <h2>物件一覧</h2>

      {/* Standard: 固定の3件表示 */}
      {!features.hasInventoryManagement && (
        <div>
          <p>おすすめ物件を3件表示</p>
          <StaticPropertyCards />
        </div>
      )}

      {/* Premium: CMS連携で動的に表示 */}
      {features.hasInventoryManagement && (
        <div>
          <p>すべての公開中物件を表示</p>
          <DynamicPropertyList />
          <Pagination />
        </div>
      )}
    </section>
  );
}
```

## 5. 業種別プラン機能

### 5.1 不動産業種

#### Standard プラン
```
- ヒーローセクション（メインビジュアル + キャッチコピー）
- 物件検索フォーム
- おすすめ物件（固定3件）
- 会社概要
- お問い合わせフォーム
```

#### Premium プラン
```
Standard の全機能 +
- 公開中物件一覧（CMS連携、ページネーション付き）
- ブログ（不動産コラム、住まいのお役立ち情報など）
- お知らせ・ニュース（新着物件情報、イベント情報など）
```

### 5.2 中古車業種

#### Standard プラン
```
- ヒーローセクション（メインビジュアル + キャッチコピー）
- 車両検索フォーム
- おすすめ車両（固定3件）
- 店舗情報
- お問い合わせフォーム
```

#### Premium プラン
```
Standard の全機能 +
- 販売中車両一覧（CMS連携、ページネーション付き）
- 販売実績（過去の販売車両）
- お知らせ・ニュース（入荷情報、キャンペーン情報など）
```

## 7. URL設計とプラン指定

### 7.1 URL構造

```
/{industry}/{plan}

例:
/real-estate/standard
/real-estate/premium
/used-car/standard
/used-car/premium
```

### 7.2 Dynamic Routes の実装

```typescript
// app/[industry]/[plan]/page.tsx

interface PageProps {
  params: {
    industry: string;
    plan: string;
  };
}

export default function IndustryPlanPage({ params }: PageProps) {
  const { industry, plan } = params;

  // バリデーション
  if (!isValidIndustry(industry) || !isValidPlan(plan)) {
    notFound();
  }

  // プラン機能の取得
  const features = getPlanFeatures(plan as Plan);

  // 業種別テンプレートのレンダリング
  return <Template plan={plan} features={features} />;
}
```

### 7.3 静的生成

全パターンを事前ビルド:

```typescript
export async function generateStaticParams() {
  const industries = ['real-estate', 'used-car'];
  const plans = ['standard', 'premium'];

  return industries.flatMap((industry) =>
    plans.map((plan) => ({
      industry,
      plan,
    }))
  );
}
```

これにより以下の4ページが静的生成されます:
- `/real-estate/standard`
- `/real-estate/premium`
- `/used-car/standard`
- `/used-car/premium`

## 9. パフォーマンス最適化

### 9.1 コード分割

Premium専用コンポーネントを動的インポート:

```typescript
import dynamic from 'next/dynamic';

const BlogSection = dynamic(() => import('@/components/BlogSection'), {
  loading: () => <p>読み込み中...</p>,
});

export default function Template({ plan }: { plan: Plan }) {
  const features = getPlanFeatures(plan);

  return (
    <div>
      {features.hasBlog && <BlogSection />}
    </div>
  );
}
```

### 9.2 条件付きバンドル

Standardプランの場合、Premium機能のコードをバンドルに含めない設計により、
初期ロードサイズを削減できます。

## 10. 拡張性の考慮

### 10.1 新しいプランの追加

将来的に「Enterprise」プランなどを追加する場合:

```typescript

  STANDARD: 'standard',
  PREMIUM: 'premium',
  ENTERPRISE: 'enterprise', // 追加
} as const;

export const getPlanFeatures = (plan: Plan): PlanFeatures => {
  // ...

  if (plan === PLANS.ENTERPRISE) {
    return {
      ...premiumFeatures,
      hasMultiLanguage: true,
      hasAdvancedAnalytics: true,
    };
  }

  // ...
};
```

### 10.2 業種別のプランカスタマイズ

業種によってプラン機能を変える場合:

```typescript
export const getPlanFeatures = (
  plan: Plan,
  industry: Industry
): PlanFeatures => {
  const baseFeatures = getBasePlanFeatures(plan);

  // 業種別のカスタマイズ
  if (industry === INDUSTRIES.USED_CAR && isPremiumPlan(plan)) {
    return {
      ...baseFeatures,
      hasSalesHistory: true, // 中古車のみ
    };
  }

  return baseFeatures;
};
```

## 11. まとめ

### 11.1 設計の利点

1. **保守性**: プラン機能が一元管理されている
2. **拡張性**: 新プラン・新機能の追加が容易
3. **型安全性**: TypeScriptによる型チェック
4. **テスタビリティ**: ロジックとUIが分離されている
5. **パフォーマンス**: 条件付きレンダリングによる最適化

### 11.2 実装の要点

- プラン判定は `getPlanFeatures()` に集約
- UI層では機能フラグを使用
- 大きなセクションは `PremiumFeatures` ラッパーを使用
- 小さな要素は直接条件分岐
- テストは各層で適切に実施
